XP First Development Cycle Task List: v0.1 Root Prototype

Cycle Goal

Complete the proposed v0.1 development cycle by producing one reproducible local match: one human player, two deterministic bots, seeded PostgreSQL content, in-memory decks and rules, visible terminal logs, and a fixed-seed simulation that can be replayed.

The domain source of truth is the Level 1 to Level 10 race through encounters, treasure, curses, help, sabotage, and readable logs. Build targets, database adapters, Docker, CMake, CTest, and NCurses are useful only when they protect that behavior or make feedback reproducible.

Reviewed Sources

  • kickoff_backlog.html: R0 through R9 proposed v0.1 cycle.
  • software_engineering_principles.html: domain-first source-of-truth rule.
  • lead_architecture_refinement_guide.html: unified increment order AR0 through AR8.
  • gameplay_refinement_guide.html: content bands, combat targets, curse expiry, bot behavior, and playtest metrics.
  • db_refinement_guide.html: seed validation, deck membership, content repository contract, and deferred event persistence.
  • systems_refinement_guide.html: layered C17 targets, deterministic RNG, command tests, ownership, and NCurses smoke path.
  • devops_refinement_guide.html: Make workflow, Docker/Compose bootstrap, DB lifecycle, simulation artifacts, and release readiness.

Working Rules

  • Write the failing test, validation query, or playtest checklist before implementation.
  • Keep pure domain/application tests independent of PostgreSQL, NCurses, sockets, pthreads, and filesystem fixtures.
  • Load seeded content at match startup; do not query PostgreSQL during each turn.
  • Use explicit seeds for shuffles, bot decisions, and simulation transcripts.
  • Route human and bot actions through application commands; the UI renders snapshots and sends intentions only.
  • Defer networking, account persistence, rankings, runtime JSONB event persistence, production deployment, and complex class abilities.

make clean
make build

make db-validate
make test-db
make simulate DTD_MATCH_SEED=<known-seed>
manual NCurses playtest checklist
architecture boundary checklist

A cycle is not complete if the fixed-seed simulation cannot replay, if content validation can start an empty match, if domain/application tests require PostgreSQL or NCurses, or if the UI owns combat, reward, curse, or bot decision rules.

Pairing Prompts

  • What player-visible rule or release risk does this task prove?
  • What is the smallest failing test, SQL validation, transcript expectation, or playtest note?
  • Which dependency must not leak into this layer?
  • What event should the UI log instead of inferring from private state?
  • What seed, fixture, or transcript will let us replay the bug?

Stop Condition

Stop the cycle when the v0.1 release gate passes and one reviewed transcript plus one manual playtest note prove the local Level 1 to Level 10 match. Do not continue into sockets, event persistence, rankings, accounts, advanced AI, or expanded card catalogs until this stop condition is met.
