T04 Implementation Plan: Validate Seeded Content Before Match Startup

Intent

Goal: Validate that the game has loaded all required starter classes and cards before initializing a match. If any required seed data is missing or invalid, fail fast at startup.

A data-driven card game depends on the content stored in its database. Rather than allowing silent failures (such as a segmentation fault when a player picks a class that wasn't loaded), the application layer must validate content definitions immediately upon loading, using a clear validation function.

Implementation Story

Source backlog item: T04, R1, AR2, DB0, DB3, GD0.

Domain behavior served: Validation of the match setup. A match can only start if we have valid classes and decks loaded.

User-visible outcome served: Transparent developer error messaging when a SQL migration or seed script is broken or out of sync.

Boundaries touched by the human: application/content.h, application/content.c, infrastructure/db/postgresql_content_repository.c, tests/application/test_content_validation.c.

Out of scope: Actually connecting to the live DB inside domain unit tests (use a mock repository instead).

Domain Invariants

The content validator must assert that the loaded content definitions satisfy the following requirements:

  • At least 6 distinct classes are loaded (Backend, Frontend, DevOps, QA, Security, AI).
  • At least 7 card types are supported (MONSTER, EQUIPMENT, CURSE, EVENT, PVP, AI, TREASURE).
  • At least 1 card of type MONSTER is present.
  • At least 1 card of type EQUIPMENT is present.
  • At least 1 card of type CURSE is present.
  • At least 1 card of type AI is present.
  • Every loaded card has a name, positive quantity, and non-empty card type.

Red Slice

  1. Write a CTest unit test that initializes an empty game_content_definitions_t struct.
  2. Call game_validate_content(&empty_content) and assert it returns false.
  3. Verify this test fails to compile or run until the validation interface is added.

Green Slice

  1. Define game_card_def_t and game_class_def_t structs in application/content.h.
  2. Implement game_validate_content() in application/content.c checking the rules described under Domain Invariants.
  3. Implement a fake repository in the unit tests that returns a subset of valid data to make the validation test pass.

Refactor Slice

  1. Isolate the data transformation logic. Let the infrastructure repository layer map database columns to plain C structs (e.g. mapping string fields to enums).
  2. Provide diagnostic messages to stderr when validation fails, specifying exactly which check failed.

Example Content Definitions header

#ifndef GAME_CONTENT_H
#define GAME_CONTENT_H

#include <stdbool.h>

typedef enum {
    CARD_MONSTER,
    CARD_EQUIPMENT,
    CARD_CURSE,
    CARD_EVENT,
    CARD_PVP,
    CARD_AI,
    CARD_TREASURE,
    CARD_TYPE_COUNT
} game_card_type_t;

typedef struct {
    char name[64];
    game_card_type_t type;
    int power;
    int power_bonus;
    int quantity;
} game_card_def_t;

typedef struct {
    int class_id;
    char name[64];
    int base_power_bonus;
} game_class_def_t;

typedef struct {
    game_card_def_t *cards;
    int card_count;
    game_class_def_t *classes;
    int class_count;
} game_content_definitions_t;

bool game_validate_content(const game_content_definitions_t *content);

#endif

Example Content Validator implementation

Human-created file: application/content.c

#include "content.h"
#include <stdio.h>
#include <string.h>

bool game_validate_content(const game_content_definitions_t *content) {
    if (!content) {
        fprintf(stderr, "Validation failed: content is NULL\n");
        return false;
    }
    if (content->class_count < 6) {
        fprintf(stderr, "Validation failed: expected at least 6 classes, got %d\n", content->class_count);
        return false;
    }
    if (content->card_count < 4) {
        fprintf(stderr, "Validation failed: expected at least 4 cards for v0.1\n");
        return false;
    }

    bool has_monster = false;
    bool has_equip = false;
    bool has_curse = false;
    bool has_ai = false;

    for (int i = 0; i < content->card_count; i++) {
        const game_card_def_t *c = &content->cards[i];
        if (strlen(c->name) == 0) {
            fprintf(stderr, "Validation failed: card at index %d has no name\n", i);
            return false;
        }
        if (c->quantity <= 0) {
            fprintf(stderr, "Validation failed: card '%s' has non-positive quantity: %d\n", c->name, c->quantity);
            return false;
        }
        if (c->type == CARD_MONSTER) has_monster = true;
        if (c->type == CARD_EQUIPMENT) has_equip = true;
        if (c->type == CARD_CURSE) has_curse = true;
        if (c->type == CARD_AI) has_ai = true;
    }

    if (!has_monster || !has_equip || !has_curse || !has_ai) {
        fprintf(stderr, "Validation failed: missing required card types (Monster:%d, Equip:%d, Curse:%d, AI:%d)\n",
                has_monster, has_equip, has_curse, has_ai);
        return false;
    }

    return true;
}

Example Content Test

Human-created file: tests/application/test_content_validation.c

#include "content.h"
#include <assert.h>

int main(void) {
    // Red: empty validation fails
    game_content_definitions_t empty = {0};
    assert(!game_validate_content(&empty));

    // Green: valid validation passes
    game_class_def_t test_classes[6] = {
        {1, "Backend Developer", 0},
        {2, "Frontend Developer", 0},
        {3, "DevOps Engineer", 0},
        {4, "QA Engineer", 0},
        {5, "Security Engineer", 0},
        {6, "AI Engineer", 0}
    };

    game_card_def_t test_cards[4] = {
        {"Legacy Code Monster", CARD_MONSTER, 5, 0, 2},
        {"ThinkPad T480", CARD_EQUIPMENT, 0, 2, 2},
        {"Broken CI", CARD_CURSE, 0, 0, 1},
        {"Prompt Intern", CARD_AI, 2, 0, 1}
    };

    game_content_definitions_t valid = {
        .classes = test_classes,
        .class_count = 6,
        .cards = test_cards,
        .card_count = 4
    };

    assert(game_validate_content(&valid));

    return 0;
}
