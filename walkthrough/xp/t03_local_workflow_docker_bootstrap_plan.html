T03 Implementation Plan: Local Workflow and Docker Bootstrap

Intent

Goal: Define a standard, repeatable Makefile interface and Docker Compose environment that developers can use locally to configure, build, test, seed, and run the simulation or interactive game client.

A C17 codebase with a PostgreSQL database dependency requires automated coordination. Manually managing configuration flags, seeding the database, running containerized instances, and executing CTests must be consolidated behind standard command wrappers to avoid custom scripts and "works on my machine" failures.

Implementation Story

Source backlog item: T03, R0, R0.5, DEV0, DEV1.

Domain behavior served: Fast feedback loop for developers checking domain rules or compiling the client.

User-visible outcome served: Contributors can bootstrap the game stack using Docker or local dependencies without encountering manual setup errors.

Boundaries touched by the human: Root Makefile, root docker-compose.yml, root Dockerfile, and documentation files.

Out of scope: Actually rewriting production files or adding new card rules.

Workflow Targets

The Makefile interface must provide the following targets:

  • make configure - Runs CMake configuration into the build directory.
  • make build - Runs the CMake build.
  • make test - Runs fast, offline domain/application tests.
  • make db-seed - Runs database initialization and seeds.
  • make db-validate - Validates database schema and seeded content constraints.
  • make test-db - Runs integration tests that require a running database.
  • make simulate - Runs the non-interactive bot playtest simulation.
  • make run - Starts the interactive NCurses UI client.

Red Slice

  1. Create a temporary, failing Makefile target check: execute a command that verifies the existence of Dockerfile or docker-compose.yml and asserts they contain the correct configuration.
  2. Assert that running make test-db fails when the PostgreSQL container is not started.

Green Slice

  1. Create the root Dockerfile that compiles the C17 targets and installs libpq-dev and libncurses-dev.
  2. Create the root docker-compose.yml file specifying the postgres:15-alpine service and the application container.
  3. Implement the Makefile targets to map locally to cmake/ctest or docker-compose execution.

Refactor Slice

  1. Do not embed passwords in the Makefile. Use standard PG environmental variables (PGPASSWORD, PGUSER, PGHOST, PGPORT, PGDATABASE).
  2. Keep Makefile paths relative.

Concrete Examples

Example docker-compose.yml

version: '3.8'

services:
  db:
    image: postgres:15-alpine
    environment:
      POSTGRES_DB: game_db
      POSTGRES_USER: game_user
      POSTGRES_PASSWORD: game_password
    ports:
      - "5432:5432"
    volumes:
      - pgdata:/var/lib/postgresql/data

  app:
    build:
      context: .
      dockerfile: Dockerfile
    environment:
      - PGHOST=db
      - PGPORT=5432
      - PGDATABASE=game_db
      - PGUSER=game_user
      - PGPASSWORD=game_password
    depends_on:
      - db
    volumes:
      - .:/workspace
    working_dir: /workspace

volumes:
  pgdata:

Example Dockerfile

FROM ubuntu:22.04

ENV DEBIAN_FRONTEND=noninteractive

RUN apt-get update && apt-get install -y \
    build-essential \
    cmake \
    libpq-dev \
    libncurses5-dev \
    libncursesw5-dev \
    postgresql-client \
    && rm -rf /var/lib/apt/lists/*

WORKDIR /workspace

Example Makefile

.PHONY: configure build test clean db-up db-down db-seed db-validate test-db simulate run

BUILD_DIR := build
DB_URL := postgresql://game_user:game_password@localhost:5432/game_db

configure:
	cmake -S . -B $(BUILD_DIR)

build: configure
	cmake --build $(BUILD_DIR)

test: build
	ctest --test-dir $(BUILD_DIR) -R "smoke|domain|application" --output-on-failure

db-up:
	docker-compose up -d db

db-down:
	docker-compose down

db-seed: db-up
	@echo "Seeding database..."
	PGPASSWORD=game_password psql -h localhost -U game_user -d game_db -f walkthrough/database/01_schema.sql
	PGPASSWORD=game_password psql -h localhost -U game_user -d game_db -f walkthrough/database/02_seed_core_data.sql
	PGPASSWORD=game_password psql -h localhost -U game_user -d game_db -f walkthrough/database/03_seed_cards.sql

db-validate: db-up
	@echo "Validating seeded content integrity..."
	# Placeholder for validation query or binary checks
	@python3 -c "print('Validation checks stub')"

test-db: build db-up
	ctest --test-dir $(BUILD_DIR) -R "db|integration" --output-on-failure

simulate: build
	./$(BUILD_DIR)/game_client_ncurses --simulate

run: build
	./$(BUILD_DIR)/game_client_ncurses

clean:
	cmake -E rm -rf $(BUILD_DIR)

Review Checks

  • Verify make db-up starts the database service correctly.
  • Verify make test runs without requiring a database connection.
  • Verify that PGPASSWORD is not stored in a plain source code file or committed configuration.

Definition Of Done

  • A developer can run make configure && make build && make test natively without Docker.
  • A developer can run make db-up && make db-seed to prepare a PostgreSQL instance.
  • The Dockerfile compiles the exact C17 dialect options (-std=c17).
  • All Makefile paths compile cleanly in the workspace shell.
