T13 Implementation Plan: Shape Command Results and Events

Intent

Goal: Define the data structures for command execution results and events in the application layer. Return structured logs, command status flags, and state snapshots rather than allowing raw console prints from inside the domain.

In Clean Architecture, the Application layer serves as a boundary interface. The UI must not interact directly with the domain state, nor should the domain log straight to stdout. Instead, commands executed in the Application layer must yield structured results detailing status, diagnostic errors, and lists of triggered match events.

Implementation Story

Domain behavior served: Communication of action results (success, failure, type of failure) and event logs back to UI or network layers.

User-visible outcome served: Screen elements redraw, errors print clearly, and audio/logs trigger for actions (such as card draws or level ups).

Boundaries touched by the human: application/command_result.h, application/command_result.c, tests/application/test_command_result.c.

Out of scope: Actually validating the game rules or processing gameplay phases (done in T14).

Event and Result Types

  • Command Status: CMD_OK (success), CMD_INVALID_PHASE, CMD_INVALID_ACTION, CMD_NOT_FOUND, CMD_ERROR.
  • Match Event: Contains a type enum (e.g. EV_LEVEL_UP, EV_CARD_DRAWN, EV_COMBAT_LOST) and a text description.
  • Command Result: Holds the status indicator, the count of events generated, and an array of events.

Concrete Examples

Example Command Result Header

Human-created file: application/command_result.h

#ifndef DTD_COMMAND_RESULT_H
#define DTD_COMMAND_RESULT_H

#include <stdbool.h>

typedef enum {
    CMD_OK,
    CMD_INVALID_PHASE,
    CMD_INVALID_ACTION,
    CMD_NOT_FOUND,
    CMD_ERROR
} game_command_status_t;

typedef enum {
    EV_MATCH_STARTED,
    EV_CARD_DRAWN,
    EV_CARD_EQUIPPED,
    EV_COMBAT_WON,
    EV_COMBAT_LOST,
    EV_CURSE_APPLIED,
    EV_LEVEL_CHANGED,
    EV_TURN_ENDED
} game_event_type_t;

typedef struct {
    game_event_type_t type;
    char message[128];
    int player_index;
} game_event_t;

#define MAX_COMMAND_EVENTS 16

typedef struct {
    game_command_status_t status;
    char error_message[128];
    game_event_t events[MAX_COMMAND_EVENTS];
    int event_count;
} game_command_result_t;

void game_result_init(game_command_result_t *res, game_command_status_t status);
bool game_result_add_event(game_command_result_t *res, game_event_type_t type, const char *msg, int player_index);

#endif

Example Command Result Implementation

Human-created file: application/command_result.c

#include "command_result.h"
#include <string.h>

void game_result_init(game_command_result_t *res, game_command_status_t status) {
    if (!res) return;
    res->status = status;
    res->error_message[0] = '\0';
    res->event_count = 0;
}

bool game_result_add_event(game_command_result_t *res, game_event_type_t type, const char *msg, int player_index) {
    if (!res || res->event_count >= MAX_COMMAND_EVENTS) return false;
    game_event_t *ev = &res->events[res->event_count++];
    ev->type = type;
    ev->player_index = player_index;
    strncpy(ev->message, msg ? msg : "", sizeof(ev->message) - 1);
    ev->message[sizeof(ev->message) - 1] = '\0';
    return true;
}

Example Command Result Test

Human-created file: tests/application/test_command_result.c

#include "command_result.h"
#include <assert.h>
#include <string.h>

int main(void) {
    game_command_result_t result;
    game_result_init(&result, CMD_OK);

    assert(result.status == CMD_OK);
    assert(result.event_count == 0);

    bool ok = game_result_add_event(&result, EV_LEVEL_CHANGED, "Senior backend dev gained Level 2", 0);
    assert(ok);
    assert(result.event_count == 1);
    assert(result.events[0].type == EV_LEVEL_CHANGED);
    assert(strcmp(result.events[0].message, "Senior backend dev gained Level 2") == 0);

    return 0;
}
