T02 Implementation Plan: Layered Build Skeleton

Intent

Goal: create the smallest build skeleton that proves Clean Architecture dependency direction before gameplay code grows.

T02 exists because the game will soon need domain rules, application commands, PostgreSQL content loading, and NCurses rendering. If those are compiled into one unstructured executable first, forbidden dependencies can spread quietly. The build must make boundary mistakes visible early.

This plan is intentionally a handoff. The human implementer will edit production files manually. Agents must not write under domain/, application/, infrastructure/, client/, server/, or shared/.

Implementation Story

Source backlog item: T02, R0, A1, SP0, DEV1.

Domain behavior served: future combat, deck, curse, and command rules can be tested in pure C without database or terminal dependencies.

User-visible outcome served: later gameplay increments can be implemented safely because the build catches misplaced rule ownership early.

Boundaries touched by the human: root CMakeLists.txt, root Makefile, minimal placeholder source/test files under the production tree, and optional support test folders.

Out of scope: real card rules, database queries, NCurses layout, Docker implementation, networking, protocol structs, and production deployment.

Target Shape

game_domain
    pure C17 domain placeholders only
    links: C standard library only

game_application
    application command/service placeholders
    links: game_domain

game_infrastructure_db
    PostgreSQL adapter placeholder only
    links: game_application, game_domain, libpq

game_client_ncurses
    terminal client placeholder only
    links: game_application, game_domain, game_infrastructure_db, ncurses

game_tests_domain
    minimal CTest smoke test
    links: game_domain

game_tests_application
    optional application smoke test
    links: game_application, game_domain

Keep server/ and shared/ empty or absent for T02 unless the repo already has them. They are v0.2 concerns and should not be used to justify protocol work in this slice.

Red Slice

  1. Create or identify a minimal domain smoke test expectation: game_domain_smoke() returns a known value such as 17.
  2. Define the desired CTest name before implementation: domain_smoke.
  3. Write down the boundary expectation: the domain test must link only game_domain.
  4. Run make test before the implementation exists. It should fail because the build skeleton or test does not exist yet.

The red state is meaningful if the failure says there is no build target, no test executable, or no test registered. Do not skip this just because the code is trivial.

Green Slice

  1. Add the smallest possible source placeholders for domain, application, infrastructure DB, and client targets.
  2. Add the root CMake target graph with strict C17 settings and CTest enabled.
  3. Add the Make wrapper for configure, build, test, and clean.
  4. Make make build pass.
  5. Make make test pass with the domain smoke test.

Green is not a gameplay milestone. It only proves the build graph and fast feedback loop.

Refactor Slice

  1. Remove any accidental target that links everything together just to make compilation easy.
  2. Make PostgreSQL and NCurses discovery local to the targets that need them.
  3. Keep include paths narrow. Prefer target-specific include directories over global include directories.
  4. Rename placeholders if needed so they describe their boundary instead of future behavior they do not yet implement.
  5. Add a short dependency review note to the PR or commit message.

Example Root CMakeLists.txt

cmake_minimum_required(VERSION 3.16)
project(GameCore C)

set(CMAKE_C_STANDARD 17)
set(CMAKE_C_STANDARD_REQUIRED ON)
set(CMAKE_C_EXTENSIONS OFF)

add_compile_options(-Wall -Wextra -Werror -pedantic)

enable_testing()

add_library(game_domain
    domain/game_domain_smoke.c
)
target_include_directories(game_domain PUBLIC domain)

add_library(game_application
    application/game_application_smoke.c
)
target_include_directories(game_application PUBLIC application)
target_link_libraries(game_application PUBLIC game_domain)

find_package(PostgreSQL REQUIRED)
add_library(game_infrastructure_db
    infrastructure/db/postgresql_content_repository_smoke.c
)
target_include_directories(game_infrastructure_db PRIVATE ${PostgreSQL_INCLUDE_DIRS})
target_link_libraries(game_infrastructure_db PRIVATE
    game_application
    game_domain
    ${PostgreSQL_LIBRARIES}
)

find_package(Curses REQUIRED)
add_executable(game_client_ncurses
    client/main.c
)
target_include_directories(game_client_ncurses PRIVATE ${CURSES_INCLUDE_DIR})
target_link_libraries(game_client_ncurses PRIVATE
    game_application
    game_domain
    game_infrastructure_db
    ${CURSES_LIBRARIES}
)

add_executable(game_tests_domain
    tests/domain/test_domain_smoke.c
)
target_link_libraries(game_tests_domain PRIVATE game_domain)
add_test(NAME domain_smoke COMMAND game_tests_domain)

add_executable(game_tests_application
    tests/application/test_application_smoke.c
)
target_link_libraries(game_tests_application PRIVATE game_application game_domain)
add_test(NAME application_smoke COMMAND game_tests_application)

Example Makefile

.PHONY: configure build test clean

BUILD_DIR := build

configure:
	cmake -S . -B $(BUILD_DIR)

build: configure
	cmake --build $(BUILD_DIR)

test: build
	ctest --test-dir $(BUILD_DIR) --output-on-failure

clean:
	cmake -E rm -rf $(BUILD_DIR)
Adapt names to the repository. These are examples, not a mandate to keep placeholder names forever. The important part is the target graph and dependency isolation.

Review Checks

Commands

make clean
make build
make test
ctest --test-dir build --output-on-failure

Manual Dependency Review

  • Search domain and application for forbidden includes: libpq-fe.h, ncurses.h, pthread.h, sys/socket.h, and netinet/in.h.
  • Confirm game_tests_domain links only game_domain.
  • Confirm game_tests_application links only game_application and game_domain.
  • Confirm game_infrastructure_db is the only target with PostgreSQL libraries.
  • Confirm game_client_ncurses is the only target with Curses libraries.

Forbidden Shortcut

Do not create a single dungeon_client or game_everything target that directly compiles domain, application, infrastructure, and client files together. That hides the dependency violations T02 is meant to expose.

Definition Of Done

  • make build passes with -std=c17 -Wall -Wextra -Werror -pedantic.
  • make test passes without a running PostgreSQL service.
  • make test does not require interactive NCurses.
  • The target graph has separate domain, application, infrastructure DB, client, and test targets.
  • The domain target links only the C standard library.
  • The application target links domain only and does not include PostgreSQL or NCurses headers.
  • PostgreSQL and NCurses dependencies are isolated to infrastructure DB and client targets respectively.
  • The PR or commit includes a short boundary review note referencing T02 and this plan.
