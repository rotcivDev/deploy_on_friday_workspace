T20 Implementation Plan: Run Release Candidate Gate

Intent

Goal: Define the final release validation sequence checking compiler compatibility, mock and database execution tests, deterministic replay, boundary isolation checks, and clean project builds.

A development cycle is only finished when its release gate passes. To ensure the v0.1 Root Prototype is stable, the release gate coordinates compilation cleanup, tests suite runs, DB verification scripts, and deterministic bot simulation replays before completing work.

Implementation Story

Source backlog item: T20, R8, R9, DEV7.

Domain behavior served: Repeatable build verification, compliance evaluation, and product validation.

User-visible outcome served: Ensure the codebase is clean, build actions are fast, and zero broken or incomplete code leaks to production branch releases.

Boundaries touched by the human: Root Makefile targets, and pipeline testing configurations.

Out of scope: Deploying compilation bundles to server clusters. Local desktop validation only.

Release Gate Checklist

Before delivering the iteration increment, verify the following steps:

  • Run make clean to remove all build outputs.
  • Run make configure to check generator output files.
  • Run make build checking that compilation warnings are zero.
  • Run make test verifying all unit tests pass.
  • Run make db-seed && make db-validate checking seeded card data is valid.
  • Run make test-db verifying integration tests connect and pass.
  • Run make simulate and verify the generated simulation_transcript.txt finishes with a winner.
  • Run a manual playtest checking keyboard controls and redraw behavior in NCurses.

Red Slice

  1. Declare a release candidate status file at walkthrough/release_status.html containing "STATUS: INCOMPLETE".
  2. Ensure running the checklist validation script fails if any unit test is broken or if compilation warnings are present.

Green Slice

  1. Address any outstanding warnings in C17 code files.
  2. Run the validation commands.
  3. Change the release status file to "STATUS: VERIFIED" and list the checked-in commit hash.

Refactor Slice

  1. Verify no residual files or debug logs are left in unit test outputs. Clear temp items.

Concrete Examples

Example Release Verification Script

Human-created file: tests/run_release_gate.sh

#!/usr/bin/env bash

set -euo pipefail

echo "=== RUNNING RELEASE CANDIDATE GATE ==="

echo "1. Cleaning previous builds..."
make clean

echo "2. Configuring and building targets..."
make build

echo "3. Running off-line unit tests..."
make test

echo "4. Seeding and validating DB templates..."
# Optionally mock or run if service is active
# make db-seed
# make db-validate

echo "5. Executing deterministic bot simulation replay..."
make simulate

echo "6. Checking for boundary leak issues..."
# Simple grepping checking for forbidden includes in domain
if grep -rn "libpq-fe.h" domain/; then
    echo "ERROR: domain layer includes libpq-fe.h!"
    exit 1
fi

if grep -rn "ncurses.h" domain/ application/; then
    echo "ERROR: core layers include ncurses.h!"
    exit 1
fi

echo "=== ALL GATE SECTIONS PASSED SUCCESSFULLY ==="

Review Checks

  • Verify the verification shell script returns a clean exit code.

Definition Of Done

  • The verification gate script runs successfully.
  • Zero compilation errors or boundary leaks are detected.
  • Deferred v0.2 features remain excluded from the candidate scope.
