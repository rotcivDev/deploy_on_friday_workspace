T15 Implementation Plan: Add Deterministic Bot Baseline

Intent

Goal: Implement the deterministic bots: Legacy Maintainer and Prompt Intern. Route all bot decisions through standard application commands, ensuring reproducibility.

In Dungeons and Devs, matches feature one human player and two bot players. The bots must make choices deterministically rather than relying on randomized algorithms. This makes tests re-runnable and ensures bot play is predictable and debuggable.

Implementation Story

Source backlog item: T15, R6, AR5, GD4, SP3.

Domain behavior served: Non-human turn progression. Selecting cards to equip or resolving combat phases.

User-visible outcome served: Bots make rapid, logical, repeatable moves during play sessions, giving players an engaging race to Level 10.

Boundaries touched by the human: application/bot_ai.h, application/bot_ai.c, tests/application/test_bot_ai.c.

Out of scope: Machine learning or neural networks. C17 bots are simple rule engines.

Deterministic Bot Behaviors

  • Legacy Maintainer: Evaluates hand. If they hold any equipment card with a power bonus > 0, they immediately equip it. When resolving an encounter, they fight the monster directly. If another player is fighting, they never help or sabotage (they stay passive).
  • Prompt Intern: Aggressively equips the first available item. If another player is in combat, they will sabotage if they hold a sabotage card and the player has higher level.

Example Bot AI Implementation

Human-created file: application/bot_ai.c

#include "bot_ai.h"

dad_command_t dad_bot_evaluate(const dad_match_t *match, int bot_player_index, dad_bot_type_t type) {
    dad_command_t cmd = {0};
    cmd.player_index = bot_player_index;

    if (!match || bot_player_index < 0 || bot_player_index >= match->player_count) {
        cmd.type = CMD_END_TURN;
        return cmd;
    }

    const dad_player_t *bot = &match->players[bot_player_index];

    if (match->phase == PHASE_START_TURN) {
        cmd.type = CMD_KICK_BACKLOG;
        return cmd;
    }

    if (match->phase == PHASE_RESOLVE_ENCOUNTER) {
        cmd.type = CMD_RESOLVE_ENCOUNTER;
        return cmd;
    }

    if (match->phase == PHASE_LOBBY_PLAY) {
        // Look for items to equip
        for (int i = 0; i < bot->hand_count; i++) {
            if (bot->hand[i]->type == CARD_EQUIPMENT) {
                cmd.type = CMD_EQUIP_CARD;
                cmd.hand_index = i;
                return cmd;
            }
        }

        // If nothing to play, end turn
        cmd.type = CMD_END_TURN;
    }

    return cmd;
}

Example Bot Test

Human-created file: tests/application/test_bot_ai.c

#include "bot_ai.h"
#include <assert.h>

int main(void) {
    dad_class_def_t test_classes[6] = {
        {1, "QA", 0}, {2, "QA", 0}, {3, "QA", 0}, {4, "QA", 0}, {5, "QA", 0}, {6, "QA", 0}
    };
    dad_card_def_t test_cards[4] = {
        {"Monster A", CARD_MONSTER, 3, 0, 5},
        {"ThinkPad", CARD_EQUIPMENT, 0, 2, 5},
        {"Curse A", CARD_CURSE, 0, 0, 5},
        {"AI A", CARD_AI, 2, 0, 5}
    };
    dad_content_definitions_t content = {
        .classes = test_classes,
        .class_count = 6,
        .cards = test_cards,
        .card_count = 4
    };

    dad_match_t match;
    int class_selections[2] = {1, 2};
    assert(dad_match_create(&match, &content, 42, 2, class_selections));

    // Current player index is 0. Transition phase to play.
    match.phase = PHASE_LOBBY_PLAY;

    // Check bot decision with equipment card in hand
    // Player index 0 is QA class, starting hand has 2 treasure cards (should have drawn ThinkPads in this test content setup)
    dad_command_t decision = dad_bot_evaluate(&match, 0, BOT_LEGACY_MAINTAINER);
    
    // Legacy maintainer equips the equipment card
    assert(decision.type == CMD_EQUIP_CARD);
    assert(decision.player_index == 0);

    return 0;
}
