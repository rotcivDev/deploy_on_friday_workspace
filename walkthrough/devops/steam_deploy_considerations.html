Steam Deployment Considerations: Deploy on Friday

1. Overview

Deploying a terminal-native, C17 game like Deploy on Friday to Steam poses unique opportunities and challenges. While Steam easily distributes executable binaries, players expect graphical overlay support, customizable window behaviors, achievements, and cross-platform plug-and-play installation. This document details the technical wrappers, library shims, and architectural integration plans for a Steam launch.

2. Terminal Packaging & Wrappers

Running a raw C binary directly relies on the operating system's default system terminal (e.g., Apple Terminal, command.exe, or PowerShell). This compromises the visual aesthetic due to unconstrained aspect ratios, missing custom font glyphs, and the inability to hook the Steam Overlay.

Recommended Solution: Package the C game inside a graphics-backed terminal renderer wrapper (such as **SDL2**, **Raylib**, or an **Electron-wrapped xterm.js** interface).

This approach captures the stdin/stdout of the game and pipes it into a dedicated window, enabling:

  • Locked aspect ratios and custom sizing parameters.
  • Retro post-processing shaders (CRT scanlines, chromatic aberration, or green-phosphor tints).
  • Steam Overlay integration (as Steam hooks into the OpenGL/DirectX/Vulkan context of the wrapper).

3. Windows Terminal Support

While NCurses is native on Linux and macOS, Windows requires special handling. To compile a single C codebase across environments, use conditional builds linking either ncurses or PDCurses:

#ifdef _WIN32
  #include <curses.h> // Links to PDCurses in Windows builds
#else
  #include <ncurses.h> // Links to standard NCurses in POSIX
#endif

This allows the same terminal client code to compile natively into a Windows console executable without forks.

4. Steamworks SDK & C Bindings

Steam features such as Achievements, Leaderboards, Rich Presence, and Cloud Saves require linking the C++ Steamworks SDK. Since our core codebase is C17, we establish flat C export bindings around the Steam API:

Example Steam C Wrapper Header

#ifndef DTD_STEAM_WRAPPER_H
#define DTD_STEAM_WRAPPER_H

#include <stdbool.h>

bool dtd_steam_init(void);
void dtd_steam_run_callbacks(void);
void dtd_steam_set_achievement(const char *name);
void dtd_steam_set_rich_presence(const char *key, const char *value);
void dtd_steam_shutdown(void);

#endif

Example Wrapper Implementation (C++)

#include "steam_api.h"
extern "C" {
    #include "steam_wrapper.h"

    bool dtd_steam_init(void) {
        return SteamAPI_Init();
    }

    void dtd_steam_run_callbacks(void) {
        SteamAPI_RunCallbacks();
    }

    void dtd_steam_set_achievement(const char *name) {
        if (SteamUserStats()) {
            SteamUserStats()->SetAchievement(name);
            SteamUserStats()->StoreStats();
        }
    }

    void dtd_steam_set_rich_presence(const char *key, const char *value) {
        if (SteamFriends()) {
            SteamFriends()->SetRichPresence(key, value);
        }
    }

    void dtd_steam_shutdown(void) {
        SteamAPI_Shutdown();
    }
}

5. DLC & Modular Content Packs

Our extension strategy (e.g., The Punch Card Era, The AI New Era) can be distributed directly as Steam DLC. At match startup, the game client queries the Steamworks API to verify product ownership before letting the player select extension decks:

bool has_ai_expansion = SteamAppHasSubscription(1234560); // Steam DLC AppID
if (has_ai_expansion) {
    // Enable AI New Era content recipes inside the startup validator
}
